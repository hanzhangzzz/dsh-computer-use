# 统筹规划（master plan）

日期：2026-08-26。这是项目的顶层地图，负责回答"先做什么、后做什么、为什么"。
细节和证据在下级文档里，本文只做排序和取舍：

- 桌面控制的技术方案 → docs/desktop-control-plan.md（目标：人机共驾）
- 现状能力与缺陷清单 → docs/capability-assessment.md
- 触发制开放项 → docs/phase3-roadmap.md

## 现状一句话

浏览器里的"给定网址、点指定元素"这类短任务已经跑通（15/15，但验收判据偏松）；
真实世界的网页（SPA、iframe、需要滚动的长页）还没验证过；桌面控制是 0，但可行性
已用实测探针证明，且不需要任何私有 API。

## 两条主线，四个步骤

两条主线：**A. 把浏览器能力从演示级做到能用级；B. 桌面控制从 0 到人机共驾 MVP。**
A 是 B 的地基（桌面 provider 会复用同一套快照/索引/验证机制），所以 A 先行，
B 可以在 A 的后半段并行启动。

### 第 0 步：修尺子（约 1–2 天）——不修，后面所有"变好了"都不可信

1. **修验收判分**：现在 15 个任务里 7 个的判据词直接写在题目里，模型复述一遍就算过；
   `url_contains` 还会去匹配模型的口头回答而不是真实到达的网址。改成只认真实落点。
2. **补测真实坐标精度**：现有的 61.8% 是让模型输出 0–1000 归一化坐标测出来的，
   而线上工具收的是绝对像素——**生产路径的精度其实从没测过**。给 bench 加绝对像素
   模式重跑一次，这个数字决定后面要不要在视觉上投入。

### 第 1 步：浏览器能力做扎实（约 1–2 周）——六个便宜的修复，全都不需要碰模型

按"防错 → 补语义 → 扩覆盖"排序：

1. **点之前先核对身份**（半天）：现在是点完才告诉你点了什么，页面若在快照和点击之间
   变了（弹出横幅等），会点错且木已成舟。改成动作前比对元素身份，不对就拒绝。
   这是桌面控制的安全前提（桌面上点错撤不回）。
2. **过滤看不见的元素**（1 小时）：快照里混着隐藏元素，模型点了会白等 5 秒超时。
3. **给元素起好名字**（1–2 天）：实测 1181 个元素里 32% 重名（github 达 48%）、6% 无名。
   名字是模型挑选目标的唯一依据，名字烂，结构路径就悄悄退化成看图猜。97% 的无名
   元素能从 title/alt 等现成属性救回来，重名的加区分后缀。
4. **穿透 shadow DOM 和 iframe**（3–5 天）：实测这两类内容对枚举完全不可见
   （构造页面 5 个按钮只找到 1 个）。支付表单、登录框大量藏在 iframe 里——这是
   一整类任务能不能做的问题，不是精度问题。
5. **加滚动**（1–2 天）：现在没有 scroll 工具，而首屏内元素占比最低只有 12%。
6. **动作后等页面真正稳定**（1–2 天）：现在写死等 300ms，SPA 渲染慢一点就拿到
   半成品快照。改成检测 DOM 静默。

完成标志：扩充验收套件（新增 SPA、iframe、强制坐标兜底任务各 5 个，用修好的判分），
在新套件上出一个可信的成功率数字。

### 第 2 步：桌面控制 MVP——人机共驾（约 2–3 周，可与第 1 步后半并行）

技术方案见 desktop-control-plan.md，此处只列顺序：

1. **seam 改多 surface 路由**（先行，纯重构）：让"一个浏览器页面"和"一个桌面应用"
   能同时在线、按名字选择。现有行为不许变，老测试全绿为准。
2. **Swift helper**：只用公开 Accessibility API（已实测：后台按计算器 8×7 回读 56，
   不抢焦点不动光标），stdio 通信，Node 侧管策略。
3. **白名单**：哪些应用允许被操作，默认空名单=默认不能动任何应用。这是 8-25 安全
   事件的直接教训，第一版就要有。
4. **按窗口截图，绝不整屏**：像素预算下 4K 整屏截图会把 20px 的按钮压到 5.6px，
   谁也认不出来。
5. **agent 可见光标**：人机共驾的另一半——用户能看见 agent 在点哪里。
6. **桌面验收套件**：人在场跑（无人值守纪律），log 级核验。

### 第 3 步：按数据触发，不排期

这些只有在前面的实测数据触发时才做（继承 phase3-roadmap 的制度）：

| 项 | 触发条件 |
|---|---|
| 外挂专用 grounding 小模型 | 新套件上落到坐标兜底的步骤 >10% 且这些步骤成功率 <70% |
| 审批/敏感动作分级 | 出现涉及付款、发送、删除的真实任务 |
| Windows 桌面（UIA） | 有 Windows 用户提需求（Codex 在 Windows 没有桌面能力，是可反超点） |
| E2B 云桌面 | 有托管部署需求 |
| Set-of-Mark 截图叠编号 | 先做快照附几何信息；仍不够再试，且必须先自测本模型对 SoM 的响应 |

## 明确不做

- 不引 macOS 私有 API（会随系统升级无预警失效，npm 分发扛不起这个排障成本）。
- 不做视觉主路径（61.8% 实测已否决，结构优先不动摇）。
- 不换模型（DeepSeek 视觉模型是既定前提，方案都围绕"怎么把它用到极限"）。
- 无人值守不跑桌面模型任务。
